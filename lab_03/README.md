Краткие теоретические сведения
1.1. Модульная организация программ и системные модули
Модуль в Python представляет собой отдельный файл с расширением .py, содержащий определения функций, переменных и классов. Модульная архитектура обеспечивает повторное использование кода и декомпозицию сложных программных комплексов.
Импорт модулей: Для подключения встроенных или внешних модулей используется оператор import module. Для импорта конкретных функций используется форма from module import function.
Точка входа __name__: при импорте модуля весь его код исполняется один раз. Чтобы отделить код тестирования от используемого функционала, применяется точка входа с проверкой специальной переменной if __name__ == '__main__':.
Системный модуль sys: Модуль sys предоставляет доступ к параметрам среды исполнения. В частности, список sys.argv содержит аргументы командной строки, переданные скрипту при запуске.
1.2. Базовые структуры данных
Python содержит четыре основные встроенные структуры данных, предназначенные для группировки и обработки наборов элементов:
• Списки (list): Упорядоченные динамические массивы элементов произвольных типов ([]). Являются изменяемыми (mutable), что позволяет добавлять (append()), сортировать (sort()) и удалять (pop(), remove(), del) элементы.
• Кортежи (tuple): Упорядоченные неизменяемые (immutable) последовательности элементов (()). Кортежи применяются для защиты данных от случайной модификации и возврата нескольких значений из функций.
• Словари (dict): Ассоциативные массивы, хранящие пары «ключ: значение» ({}). Ключи должны быть уникальными и неизменяемыми объектами (строки, числа, кортежи).
• Множества (set): Неупорядоченные коллекции уникальных элементов. Поддерживают математические операции: объединение (|), пересечение (&), разность (-).
1.3. Индексация и операции срезов
Последовательности (списки, кортежи, строки) поддерживают обращение к элементам по индексам и получение фрагментов с помощью срезов. Синтаксис среза имеет вид [start:stop:step], где start — начальный индекс (включительно), stop — конечный индекс (не включительно), step —шаг извлечения элементов.
Отрицательные индексы: Отрицательные индексы отсчитываются от конца последовательности: -1 соответствует последнему элементу.
Разворот последовательности: Срез со значением шага -1 (например, sequence[::-1]) выполняет быстрый разворот последовательности в обратном порядке.
1.4. Системная переменная sys.argv в Python
sys.argv — это специальная переменная (список строк) из системного модуля sys в языке Python, которая содержит аргументы командной строки, переданные программе при ее запуске из консоли.
1.5 Структура и индексация списка sys.argv
• sys.argv[0] — всегда содержит имя самого запускаемого файла программного скрипта (или путь к нему).
• sys.argv[1], sys.argv[2], ... — хранят текстовые параметры и флаги, переданные программе через пробел после её имени при консольном запуске.

Задание было выполнено в двух файлах — main.py и variant_mod.py — по следующим причинам:
1.	Разделение ответственности (Separation of Concerns). Файл variant_mod.py содержит только бизнес-логику: функции search_component, get_low_stock и get_storage_zones, которые выполняют обработку данных склада. Файл main.py отвечает за точку входа, разбор аргументов командной строки и вывод результатов. Такое разделение упрощает понимание, сопровождение и тестирование кода.
2.	Повторное использование кода. Функции из variant_mod.py могут быть импортированы в другие программы (например, в систему управления AGV или в веб-интерфейс склада) без необходимости копировать их. Это соответствует принципу DRY (Don't Repeat Yourself).
3.	Демонстрация механизма импорта. Лабораторная работа направлена на изучение модульной архитектуры Python. Создание собственного модуля и его импорт в главный файл позволяет на практике освоить синтаксис from module import function и убедиться в работоспособности механизма.
4.	Изоляция точки входа. Благодаря проверке if __name__ == "__main__": файл main.py может быть запущен как самостоятельная программа, а variant_mod.py — использован как библиотека. Если бы весь код находился в одном файле, его нельзя было бы импортировать без выполнения тестового сценария.
5.	Удобство отладки и версионирования. При изменении логики обработки данных (например, добавлении новой функции) достаточно отредактировать только variant_mod.py, не затрагивая интерфейсную часть. Это снижает риск внесения ошибок в точку входа.
Таким образом, двухфайловая структура не является избыточной, а представляет собой осознанное применение принципов функционально-модульного программирования, заявленных в теме лабораторной работы.

Код для решения задания
```bash
Функция main в файле main.py
import sys
from variant_mod import search_component, get_low_stock, get_storage_zones
def main():
    min_qty = int(sys.argv[1]) if len(sys.argv) > 1 else 50
    inventory = {
        'Resistor 10k': (120, 'Zone-A'),
        'Capacitor 100uF': (30, 'Zone-B'),
        'Microcontroller': (15, 'Zone-A'),
        'Relay 12V': (80, 'Zone-C'),
    }
    print("=== УЧЕТ АВТОМАТИЗИРОВАННОГО СКЛАДА ===")
    low_stock = get_low_stock(inventory, min_qty)
    print(f"Дефицитные детали (<{min_qty} шт): {low_stock}")
    zones = get_storage_zones(inventory)
    print(f"Буквенные зоны хранения (set): {zones}")
if __name__ == "__main__":
    main()
Описание функций в файле variant_mod.py
"""Модуль учёта автоматизированного склада (AGV)."""
def search_component(inventory_dict, item_name):
    """Ищет компонент в словаре ячеек складирования.
    Возвращает кортеж (qty, zone) или None, если компонент не найден."""
    return inventory_dict.get(item_name)
def get_low_stock(inventory_dict, min_qty):
    """Возвращает список кортежей (item, qty) для компонентов с остатком < min_qty."""
    return [(item, qty) for item, (qty, zone) in inventory_dict.items() if qty < min_qty]
def get_storage_zones(inventory_dict):
    """Извлекает множество уникальных буквенных зон хранения."""
    return {zone for (qty, zone) in inventory_dict.values()}
```
